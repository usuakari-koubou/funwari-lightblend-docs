# ふんわり消灯ギミック コンポーネントガイド

ふんわり消灯ギミックに含まれるコンポーネントの一覧と、それぞれの設定項目をご説明します。

ほとんどの値は付属のエディタウィンドウで自動設定されるため、通常は手動で触る必要はありません。
**「何を変えたら何がどう変わるのか」を確認したいとき**にこのガイドをご参照ください。

---

## メインウィンドウの設定

`Tools > ふんわり消灯ギミック > メインウィンドウ` から開きます。上部の「ガイド」「ダッシュボード」「プレビュー」で表示を切り替えます。

- **ガイド**: 「準備」「シェーダー変換」「振り分け」「ペア生成」「ベイク」「仕上げ」の6工程を順に操作します（旧・工程6「仕上げ」はベイクに統合され、旧・工程7「調整」がいまの「仕上げ」です）
- **ダッシュボード**: 全工程の完了、未実行、再実行が必要な状態をまとめて確認します
- **プレビュー**: 工程ではなく成果物を眺めるためのタブです。ベイクした消灯側の結果を Play モードに入らずシーンビューで確かめられます。詳しくは [QuickStart.md の「プレビューを使う」](quickstart.md#確認する)をご覧ください

### ライトマッパー選択

「ベイク」ステップの「ライトマッパー:」で選びます。

| 選択肢 | 動作 |
|-------|------|
| **Bakery** | Bakery を使ってベイクします。未導入の場合は選べません |
| **Unity Builtin** | Unity 標準ライトマッパーを使います |

ベイクサイクルの途中で変更すると、点灯用と消灯用のライトマップが不整合になる場合があります。変更する場合は Step 1 からやり直してください。

### 一括実行とチェックポイント

「ベイクを実行する」はベイクの4回（消灯ベイク・消灯プローブ・点灯ベイク・点灯プローブ）を順に進めます。「消灯の見た目を確認してから続ける」をオンにすると、消灯側のベイク後に一時停止します。確認後は「確認できたので続ける」を押します。

設定は次の EditorPrefs に保存されます。

| EditorPrefs キー | 型 | 初期値 | 役割 |
|------------------|----|--------|------|
| `UsuakariKoubou.FunwariLightBlend.UI.v1.BakeCheckpoint` | bool | false | Step 2後の確認で一時停止する |
| `UsuakariKoubou.FunwariLightBlend.UI.v1.BakeStartTimeoutSec` | float | 120 | Runner が開始を応答するまでの秒数 |
| `UsuakariKoubou.FunwariLightBlend.UI.v1.BakeWatchdogMin` | float | 45 | 進捗を取得できないベイクの絶対監視時間（分） |

進捗を取得できるベイクでは、600秒間変化がない場合もタイムアウトとして安全停止します。この600秒は固定値です。

> リロード後は実行中だったベイクを自動再開しません。RecoveryRequired として復元操作を提案します。「シーンを点灯状態に戻す」を押してから再実行してください。

### 既存シーンの取り込みバー

旧バージョンでセットアップ済みのシーンでは、上部に「既存シーンの成立済み ○ 工程を完了として取り込めます」と表示されます。

- **取り込む**: 現在の成果物が成立している工程を完了として記録します
- **閉じる**: その時点の案内を閉じます

取り込み対象は「準備」から「仕上げ」までです。シーンを保存してから「取り込む」を押してください。

### 部屋別調光

部屋ごとに明るさを調整したい場合は、次の順で設定します。

0. 「準備」ステップの「使う機能を選ぶ」で「部屋ごとに明るさを変える」をオンにします。オフのままだと、以降の部屋関連の操作は画面に出ません。すでにシーンに部屋があるとオンのまま固定されます。
1. シーン内に部屋ボリュームを配置し、各部屋の範囲を設定します。
2. Light Volume を自動配置する場合は、「ベイク」タブの部屋セクションで「部屋から Light Volume を生成」を押します。部屋ボリュームごとに範囲を各方向へ 0.8m 広げた Light Volume が作られ、隣室との境目で明るさが急に変わらないように重なります。手置きの Light Volume がある部屋は自動生成をスキップします。
3. 「ベイク」ステップでライトを部屋へ割り当てます。
4. 「ベイク」ステップでベイクを実行します。完了後、部屋別の調光スライダーが自動生成されます。

部屋別調光のライトマップは寄与マスク方式を使用します。部屋の境界をまたぐ漏れ光は、寄与マスクが自動的に発生元の部屋へ帰属させるため、手動で調整する必要はありません。

部屋別調光では、部屋ごとの Light Volume を純寄与として個別にベイクし、消灯ベースへ加算します。加算合成される Light Volume の最大重なり数も算出し、`AdditiveMaxOverdraw` が不足していれば自動的に引き上げます。手動で設定した値が必要数より大きい場合は下げません。

消灯ベースは**ワールド全体を覆う1枚**（`Funwari_UnlitBaseLightVolume`）です。VRChat の Light Volumes は重なった非加算のボリュームを上位2枚までしか合成せず、3枚目以降は無視するため、消灯ベースを部屋ごとに持つと、3部屋が接する場所などで部屋の色が正しく合成されません。消灯ベースを1枚にまとめることで、実行時に有効な非加算が常に1枚になり、部屋の純寄与はすべて加算で積み上がります。

部屋ごとの消灯側 Light Volume は、ベイク後に**無効化された状態でシーンに残ります**。削除はしません。再ベイクのときに復帰させるために必要なためです。手動で削除しないでください。

**非加算の Light Volume を手で増やさないでください。** 共用 Light Volume を使う構成では実行時の非加算が2枚になります。2枚までは合成されますが、そこへ手置きの非加算を足すと3枚目になり、いずれかが無視されて意図しない明るさになります。ベイクタブの診断で警告します。

#### 制約

- 部屋は最大8個です。
- VRC Light Volumes が必要です。
- 部屋別スライダーの自動生成には同梱の LuraSwitch2 (QuickBrown) が必要です。
- OFF グループ、shadowmask、Light Probes Blending は部屋別ではなく全体スライダーに追従します。Reflection Probe（映り込み）は v1.3 から部屋別に分離できます（後述）。
- 部屋別調光を使わない場合は、部屋ボリュームをすべて削除してから割り当てを実行してください。従来の全体調光として動作します。
- 自動生成する部屋別の Light Volume は、箱形の部屋ボリュームの配置に依存します。複雑な形状の部屋では、Light Volume を手動で配置する必要がある場合があります。

#### ベイク回数と時間の目安

部屋数を N とすると、共用ライトがある場合は N+2 回、共用ライトがない場合は N+1 回のベイクを実行します。

2部屋と共用ライト1灯のテストシーン（Progressive GPU・低サンプル）では、部屋パス2回を含むベイク一式は約50秒でした。部屋なしの同シーンも約50秒で、小規模シーンでは増分は誤差レベルでした。大規模ワールドでの増分は部屋数とシーン規模に依存します。

#### 映り込みの部屋別分離（v1.3）

金属や光沢のある床・什器に映り込むリフレクションプローブの反射も、部屋ごとの純寄与として個別にベイクし、消灯ベースへ加算できます。ある部屋を消灯すると、その部屋の明かりが映り込みからも消え、他の部屋の映り込みはそのまま残ります。

有効にするには、リフレクションプローブを**ツールの管理下**に置く必要があります。「リフレクションプローブを検出して割り当てる」ボタンで検出・割り当てを行ってください。管理下に無い素の Reflection Probe は分離の対象になりません（ベイク自体は成功するため気づきにくく、その場合はベイクタブの診断が警告します）。

映り込みの分離もプローブ数と部屋数に比例してコストが増えます。

- **VRAM**: 映り込み用のキューブマップが「プローブ数 ×（部屋数 + 1）」枚増えます。解像度256・BC6H圧縮・フルミップの構成では1枚あたり約0.5MBが目安です。プローブ数や部屋数が多い場合はベイクタブの診断が警告します。
- **ベイク時間**: プローブの再レンダー回数が「プローブ数 ×（部屋数 + 3）」回増えます。
- **描画コスト**: 光沢面のピクセルごとにテクスチャ参照数が増えます（部屋8個構成の最悪ケースで18回）。使わない参照は実行時に読み飛ばしますが、部屋数が多い構成の光沢面は相応に重くなります。

**制約**:
- Poiyomi 系シェーダーはそもそも映り込みに対応していないため、映り込みの部屋別分離も対象外です。
- 実行中にバインド先のプローブが切り替わる動的なオブジェクトは対象外です。どのプローブの映り込みを使うかはベイク時に確定します。
- `reflectionOffIntensity`（消灯時の映り込みの強さ）は全体スライダーの消灯度合いに追従します。**通常の部屋別消灯そのもの**（ある部屋の照明を落として、その部屋の映り込みを分離する操作）にはこの倍率はかかりません。全体を点灯したまま特定の部屋だけを消灯しても、その部屋の映り込みの分離結果に補正はかかりません。**ただし部屋ごとの非常灯を設定している場合は例外**で、非常灯の映り込みには消灯側の映り込みと同じくこの倍率が掛かります。かかり方は全体一律ではなく、その部屋自身の消灯割合（部屋のスライダーの t）に応じて連続的に変化します。
- Mochie を使っている場合、映り込みには LTCGI / AreaLit / SSR の効果も混ざります。これらを併用しているマテリアルでは、消灯時の映り込み（基準）にもその効果が残ります（既定の `reflectionOffIntensity` では影響しません）。
- `Filamented_Roughness_LightmapBlend` は他の機能をすべて有効にした最悪の組み合わせだとテクスチャサンプラー数の上限に近づきます。多機能を同時に使う場合は注意してください。

### 部屋の設定（工程）

「部屋ごとに明るさを変える」がオンのときだけ、ステップ3と「昼夜」（またはステップ4）の間に番号のない「部屋」の工程が出ます。

| 項目 | 内容 |
|------|------|
| 状態 | 足りないものを理由付きで並べます。部屋の箱（`FunwariRoomVolume`）が1つ以上あるか、割り当ての検証が失敗していないか、全部屋に生成済みの Light Volume の元があるか |
| 部屋の一覧 | 部屋ごとに「箱 n 個 / 生成元 あり・なし」を表示します |
| 部屋を追加 | 部屋の箱（`FunwariRoomVolume`）を1つ作ります。箱の位置と大きさは部屋に合わせて手動で調整します |
| 割り当てを確認 | ステップ3で「点灯」にしたライトと発光が、どの部屋に入るかを箱の位置で確かめます。書き換えは行いません（`RoomSetupService.PreBake`） |
| 部屋ごとの Light Volume の元を作る | 部屋ごとに Light Volume の元だけを作ります。点灯/消灯のペア、消灯ベース、昼夜の Light Volume はステップ4「ペア生成」がまとめて作ります |
| Light Volume を広げる上限 (m) | 部屋ごとの Light Volume の箱を「部屋の箱 + ライトの到達距離」で作るときの、到達距離の上限。`LightmapChanger` に保存されます。下げるとメモリが減りますが、下げすぎると隣室のアバターがその部屋の消灯に反応しなくなります。箱を手で広げてもよい（ベイク前に。他の部屋と同一の箱にはしない） |

> ここで作るのは部屋ごとの Light Volume の元だけです。ステップ4「ペア生成」が、共用と部屋の元を
> まとめて点灯/消灯のペアにし、消灯ベースと昼夜の Light Volume も作ります。ベイク後にマスクと
> 結線を作り直したいときは、ステップ5（ベイク）の「部屋別調光」にある「マスクと結線をやり直す」を使います
> （ベイク成果物が要るため、この工程には置いていません）。

### 昼夜の設定（工程）

「昼と夜を切り替える」がオンのときだけ、ステップ3のあと（部屋機能を使う場合は「部屋」の工程のあと）に番号のない「昼夜」の工程が出ます。

| 項目 | 内容 |
|------|------|
| 状態 | 足りないものを理由付きで並べます。昼と夜の両方に光源があるか、昼と夜の光の向きが設定されているか、（Unity 内蔵のとき）環境設定を取り込んだか |
| 昼夜の環境設定 | Unity 内蔵のときだけ表示。昼と夜の Lighting を取り込み、当てて見る／戻すができます |
| 空・天体の振り分けから、昼と夜の光の向きを設定する | 「昼夜」の工程の「太陽と月」「その他の空・天体」で選んだ昼と夜の光源から向きを取り、`LightmapChanger` の Sky Day Light Source / Sky Night Light Source に設定します。Directional Light が無い側には、向きを決めるための空のオブジェクト（`Funwari_DayDirection` / `Funwari_NightDirection`）を作ります |
| リアルタイムの太陽を置く | 既定オフ。オンにすると、太陽を動かすコンポーネント（`FunwariRealtimeSun`）とリアルタイムの Directional Light、月の向きを決めるための空のオブジェクト（`Funwari_MoonDirection`）を作ります。オン／オフの状態は、そのコンポーネントがあるかどうかです。オンの間、空・天体グループの Realtime／Mixed の Light の強さは 0 になります。直射はリアルタイムの太陽が担当します |
| 昼夜で明るさを変える Light | 「昼と夜の光の向きを設定する」を押すと、空・天体グループの Baked 以外（Realtime／Mixed）の Unity Light を `LightmapChanger` の `skyDayLights` / `skyNightLights` に入れます。実行時は昼の Light を 元×d、夜の Light を 元×(1−d) の強さにし、実質 0 なら無効化して影の計算を止めます。Baked の Light は実行時に何も出さないので入れません。画面には「昼夜で明るさを変えるもの n 個 / ベイク済みなので対象外 m 個」と出ます。ベイクの実行中は設定できません |

> **注意**: Mixed の Light を実行時に弱めても、ベイクされた間接光は消えません（夜に昼の間接光が残ります）。夜の光源を地平線の下向きに置いて Realtime のままにすると、夜は下から照らします。向きは利用者の責任です。空・天体の Light が点灯／消灯グループにも入っている場合は、明るさを変える対象から外し、警告を出します。

この工程の完了と、ベイクの開始条件は同じ判定です。空・天体の光源や環境設定を変えるとベイクが要再実行になり、ベイクし直すまで戻りません（`LightmapChanger` の参照やリアルタイムの太陽だけを変えた場合は、この工程だけが要再実行になります）。

## コンポーネント一覧

| コンポーネント | 役割 | 配置場所 |
|--------------|------|---------|
| **LightmapChanger** | 全体を制御する本体。点灯/消灯の切り替えを担当 | シーン内に 1 つ |
| **LightmapChanger_ON** | アニメーター連動で「点灯状態」に切り替えるトリガー | スイッチ内部 |
| **LightmapChanger_OFF** | アニメーター連動で「消灯状態」に切り替えるトリガー | スイッチ内部 |

> スイッチ内部のコンポーネント（LightmapChanger_ON / _OFF / Controller_LightmapBlend）は、エディタウィンドウから「点灯スイッチを置く（Switch_Light）」「調光スライダーを置く（Slider_Night）」を実行したときに自動的に配置されます。手動で触る必要はほぼありません。

## LightmapChanger（本体コントローラー）

シーンの点灯/消灯を切り替える本体です。エディタウィンドウから「消灯を制御するオブジェクトを作る」ボタンで設置されます。
設定項目が多いですが、大半はエディタが自動設定するので、ご自身で触っていただくのは「クロスフェード設定」と「アンビエント設定」あたりだけです。

Inspector は上から「登録状況」（対象レンダラー・ライト・発光・部屋の登録件数を読み取り専用で表示）、「よく使う設定」、「その他の設定（任意）」、「ツールが自動設定する項目」の順に並びます。最後の折り畳みは既定で閉じており、開くと「ここを手で変えると次のベイク/振り分けで上書きされます」という警告が出ます。手で触ってよいのは「よく使う設定」と「その他の設定」だけだと考えてください。

### ライトマップ設定

> 「仕上げ」ステップの「消灯時のライトマップを割り当てる」ボタンで設定されるため、通常は触る必要がありません。

| 設定 | 説明 | デフォルト |
|-----|------|----------|
| **lightmapsOff** | 消灯時のライトマップテクスチャ（自動設定） | - |
| **lightmapsOffDir** | 消灯時の方向ライトマップ（Directional Lightmap 用、自動設定） | - |
| **targetRenderers** | ライトマップ切り替え対象のレンダラー（自動検出） | - |
| **lightVolumeIndexOffset** | Light Volume によるライトマップインデックスのずれ補正 | 0 |
| **autoCalculateOffset** | 上記オフセットをランタイムで自動計算する | ON |

### VRC Light Volumes

> アバターなど動くオブジェクトの色味を切り替えるための設定です。エディタの「Light Volumeを検出して割り当てる」ボタンで自動設定されます。

| 設定 | 説明 | デフォルト |
|-----|------|----------|
| **lightVolumeManager** | シーン内の LightVolumeManager（自動設定） | - |
| **lightVolumeInstancesOn** | 点灯時用の Light Volume 群（自動設定） | - |
| **lightVolumeInstancesOff** | 消灯時用の Light Volume 群（自動設定） | - |
| **disableLightProbesOnOff** | 消灯時に Light Probes ブレンドを無効にする | OFF |
| **lvIntensityFloor** | Light Volume の強度下限。0 にすると重なり領域の合成が不連続になる環境で、わずかな強度を維持するための調整値 | 0.0001 |

**Poiyomi のライティングモード**：
Poiyomi はライティングモード（Lighting Type）が Realistic のときだけライトマップを読みます。他のモードのマテリアルは変換しても点灯/消灯が効きません（変換前からライトマップを読んでいません）。ライトマップに焼き込む壁や床の Poiyomi マテリアルは Realistic にしてください。

**Light Volume とライトマップ済みの面**：
変換後のシェーダーは、ライトマップ済みの面では Light Volume の箱（Additive を含む）を読みません。読むのは Point Light Volume だけです。
このツールの点灯側 Light Volume は Additive で、Light Volume 対応シェーダーだとライトマップにも投影されて点灯の光が二重に乗るためです。
Light Volume の箱はアバターや動的なオブジェクトのため、ライトマップ済みの面はライトマップの合成が担当します。

**disableLightProbesOnOff について**：
Light Volume の影響範囲外にあるオブジェクトは、デフォルトでは Light Probes（点灯状態でベイクされた値）の影響を受け続けます。「消灯したのに一部のアバターだけ明るく見える」と感じた場合は、こちらを ON にすると改善することがあります。

### アンビエント設定（フォールバック）

> Light Volume が届かない場所の明るさを補う設定です。**消灯時の見た目を微調整するときに、ここをよく触ります。**

| 設定 | 説明 | デフォルト |
|-----|------|----------|
| **useAmbientFallback** | アンビエント光も連動して変化させる | ON |
| **ambientIntensityOn** | 点灯時のアンビエント強度 | 1.0 |
| **ambientIntensityOff** | **消灯時のアンビエント強度** | 0.1 |
| **ambientColorOn** | 点灯時のアンビエントカラー | 白 |
| **ambientColorOff** | **消灯時のアンビエントカラー** | 暗い青灰色 |

**調整のコツ**：
消灯時に「全体的に暗すぎる / 明るすぎる」と感じた場合は `ambientIntensityOff` を、「夜らしい青みが欲しい / もっと暖色にしたい」と感じた場合は `ambientColorOff` を調整してください。Play モード中でも値を変えながら確認できます。

**動作条件（重要）**：
この設定はランタイムに `RenderSettings`（Unity の **Environment Lighting** 設定）を上書きします。

- `ambientColorOn/Off` が反映されるのは **Environment Lighting の Source が「Color」のとき**だけです（Skybox / Gradient のままだと変化が見えません。「仕上げ」ステップに警告が出ます）
- `ambientIntensityOn/Off` は Source が「Skybox」のときの強度倍率ですが、ベイク済みシーンではランタイム変更が反映されない場合があります
- ライトマップをベイクした**静的オブジェクトには影響しません**。Light Volume 範囲外の**動的オブジェクト向けフォールバック**です

### Light/Emission 制御

> 「振り分け」ステップでの操作に応じて自動設定されます。Inspector から手動で触る必要はありません。
>
> 振り分けは「消灯の影響を受けるものを選ぶ」操作です。振り分けなかったオブジェクトは「常時」として扱われるため、シーン内の全てを振り分ける必要はありません。

#### ON グループ（点灯時に光るライト）

| 設定 | 説明 |
|-----|------|
| **blendTargetLights** | ON グループの Light コンポーネント |
| **blendTargetEmissionRenderers** | ON グループの Emission レンダラー |
| **originalEmissionColors** | Emission の元の色（自動記録） |

#### OFF グループ（消灯時に光るライト）

| 設定 | 説明 |
|-----|------|
| **offGroupLights** | OFF グループの Light コンポーネント |
| **offGroupEmissionRenderers** | OFF グループの Emission レンダラー |
| **offGroupOriginalEmissionColors** | Emission の元の色（自動記録） |

| 設定 | 説明 | デフォルト |
|-----|------|----------|
| **emissionPropertyName** | Emission のシェーダープロパティ名 | `_EmissionColor` |

> 一般的なシェーダーは `_EmissionColor` で動作します。特殊なシェーダーをお使いで Emission がうまく切り替わらない場合のみ、シェーダーのプロパティ名に合わせて変更してください。
>
> **実行時に反映されるのは、この LightmapChanger 側の `emissionPropertyName` 1本だけです。** `LightmapBlendTarget` 側にも同名の設定がありますが、そちらは「振り分け」ステップで色を検出するためだけに使われ、実行時の切り替えには使われません（両者は独立した値で、対象ごとに変えても実行時の挙動は変わりません）。異なる発光プロパティ名のオブジェクトを混在させたい場合、現状は対応していません。すべて同じ発光プロパティ名のシェーダーに揃えてください。

### Reflection Probe（映り込み）

> エディタの「リフレクションプローブを検出して割り当てる」ボタンで自動設定されます。

| 設定 | 説明 | デフォルト |
|-----|------|----------|
| **useReflectionProbeBlend** | Reflection Probe のブレンドを有効にする | ON |
| **reflectionProbesOn** | 点灯時の Reflection Probes（自動設定） | - |
| **reflectionProbesOff** | 消灯時の Reflection Probes（自動設定） | - |

> ベイクが完了すると、シーンでは点灯側の Reflection Probe だけが有効になります。消灯側はキューブマップをアセットとして参照するため、シーン上で有効にする必要はありません。両方を有効にすると、エディタでどちらの反射が使われるか不定になります。
| **reflectionCubemapsOff** | 消灯時のキューブマップ（レンダラーごと、自動設定） | - |
| **reflectionOffIntensity** | **消灯時の映り込みの強さ** | 1.0 |

**reflectionOffIntensity について**：
消灯時の金属面の映り込みが暗すぎると感じた場合に、1.5〜2.0 くらいまで上げてみてください。この値は**全体スライダーの消灯度合い**に追従します。部屋別調光と映り込みの分離（v1.3、[部屋別調光](#部屋別調光)を参照）を使っている場合、特定の部屋だけを消灯する操作そのものにはこの倍率は掛かりません。**例外は部屋ごとの非常灯**（「消灯時のみ」対象に部屋の非常灯を割り当てている場合）で、非常灯の映り込みにはその部屋の消灯割合に応じてこの倍率が掛かります。

### クロスフェード設定

> 点灯/消灯の切り替えにかかる時間や、切り替え方の見た目を調整します。**よく触る設定です。**

| 設定 | 説明 | デフォルト |
|-----|------|----------|
| **blendDuration** | クロスフェードにかかる時間（秒） | 1.0 |
| **useEasing** | 切り替えに緩急をつける | ON |

#### blendDuration

スイッチ（ON/OFF トグル）で切り替えるときに、何秒かけて変化するかを指定します。

| 値 | 印象 |
|----|------|
| 0.5 秒 | すばやく切り替わる |
| 1.0 秒 | 標準的な速さ |
| 2.0 秒以上 | ゆったり切り替わる |

> スライダー（中間値対応）で操作する場合は、つまみの位置がそのままブレンド値になるため、この設定は影響しません。

#### useEasing

ON にすると、切り替えの始まりと終わりがゆるやかになり、より自然に見えます。
OFF にすると一定速度で切り替わります。通常は ON のままで問題ありません。

### 消灯の見え方（ディミングカーブ / v2.6.0）

> 消灯時に「明るい場所ほど最後まで灯って見える」本物の調光のような見え方にできます。Inspector で直接編集するより、メインウィンドウの「**仕上げ**」ステップにあるスライダーで調整するのがおすすめです。

| 設定 | 説明 | デフォルト |
|-----|------|----------|
| **dimCurveTau** | 「明るい場所の粘り」の内部値（0 で無効 = 従来どおりの均一な消灯）。「仕上げ」ステップのスライダーから設定されます | 0 |
| **lightVolumeRepresentativeLum** | Light Volumes を粘りに連動させるための内部値。「Light Volumeを検出して割り当てる」ボタンを押すと自動計算されます。手動で変更する必要はありません。**Light Volume をベイクし直したときは、このボタンをもう一度押して再計算してください**（古い値のままだとアバターの粘り方が周囲とズレます）。**部屋を設定している場合はベイクの中で自動計算されるため、このボタンでは再計算されません**（ボタンを押しても値は変わりません） | 0 |

#### 明るい場所の粘り（仕上げステップのスライダー）

スライダーを上げるほど、照明のまわりの明るい場所が粘ってから消えるようになり、光だまりが照明に向かって縮んでいくような見え方になります。

| 値 | 印象 |
|----|------|
| 0 | 従来どおり（全体が均一に暗くなる） |
| 中間 | ほんのり粘る、自然な消え方 |
| 最大 | 明るい場所がはっきり残る |

> ベイク済みライトマップの上に実行時に掛かるパラメータなので、**ベイク後にいつでも変更できます**（再ベイクは不要です）。
> 「仕上げ」ステップで「ライブプレビュー」をオンにすると、シーンビューに消灯の様子が反映されます。なお、消灯後に残る明かりはシミュレートされません。点灯ライトの消え方のみがプレビュー可能です。
> この効果は「明るい場所と暗い場所の差」を材料にするため、均一に照らされた部屋では変化が控えめになります。ランプやスポットライトの光だまりがあるシーンでよく映えます。

### 同期設定

| 設定 | 説明 | デフォルト |
|-----|------|----------|
| **instantSyncForLateJoiner** | 後から参加した人にも即座に状態を反映する | ON |

ON にすると、ワールドに後から入室したプレイヤーにも、入室と同時に現在の点灯/消灯状態が反映されます。通常は ON のままにしてください。

### デバッグ設定

| 設定 | 説明 | デフォルト |
|-----|------|----------|
| **debugMode** | Console にデバッグログを出力する | OFF |

問題が起きた場合に ON にすると、初期化やブレンドの状態が Console に表示されます。トラブルシュート時のみご利用ください。

## FunwariRealtimeSun（リアルタイムの太陽を動かすコンポーネント）

「昼夜」の工程の「リアルタイムの太陽を置く」で作られます。`LightmapChanger` の `daylight` を毎フレーム読み、リアルタイムの Directional Light を動かします。空の向きは書きません（`LightmapChanger` が書きます）。このコンポーネントがある間（`LightmapChanger` の `realtimeSun` が指している間）、空・天体グループの Realtime／Mixed の Light の強さは 0 になります。直射が二重にならないためです。シーンの `RenderSettings.sun` がリアルタイムの Directional Light なら新しく作らずそれを使い、向きと強さはこのコンポーネントが変えます。

| 項目 | 内容 |
|------|------|
| `changer` | 昼夜の値を読む `LightmapChanger` |
| `sun` | 動かすリアルタイムの Directional Light |
| `dayDirection` / `moonDirection` | 昼と夜（月光）の向きを決めるための空のオブジェクト。月光は下向きに置きます。夜空を作るために地平線の下を向いた光源を照明に使うと天井を下から照らすため、空の向きとは別に持ちます |
| `dayIntensity` / `nightIntensity` | 昼と夜の強さ。夜を 0 にすると夜はライトを無効化し、影の計算も止まります |
| `dayColor` / `nightColor` / `duskColor` / `duskDip` | 昼・夜・夕方の色と、夕方に強さを落とす量。昼→夜が「回る」でなく「暮れる」に見えます |

## LightmapBlendTarget（ライト/発光のマーカー）

シーン内のライトや発光オブジェクトに個別にアタッチして、消灯時の挙動を指定するマーカーコンポーネントです。

「振り分け」ステップでの操作に応じて、対象オブジェクトへ自動的に追加されます。

### 基本設定

| 設定 | 説明 | デフォルト |
|-----|------|----------|
| **targetType** | 制御対象の種類 | Auto |
| **blendGroup** | 振り分けグループ | 点灯 |
| **emissionPropertyName** | Emission のプロパティ名（振り分け時の色検出にのみ使用。実行時の切り替えには使われません） | `_EmissionColor` |

#### targetType

このオブジェクトの何を制御するかを指定します。

| 値 | 内容 |
|----|------|
| **Auto** | Light コンポーネントと Emission の両方を自動判定して制御（通常はこれ） |
| **Light** | Light コンポーネントのみ制御 |
| **Emission** | Emission（発光マテリアル）のみ制御 |

#### blendGroup

このオブジェクトをどのグループに振り分けるかを指定します。

| 値 | 動作 | 例 |
|----|------|-----|
| **点灯** | 点灯時に明るく、消灯時に暗くなる | メイン照明、蛍光灯 |
| **常時** | 状態に関係なく常に同じ明るさ | 装飾 LED、機械のインジケーター、自前アニメで動く看板 |
| **消灯時のみ** | 消灯時に明るく、点灯時に目立たない | 非常灯、星空、蓄光素材 |

> 振り分けはメインウィンドウの「振り分け」ステップで一覧操作します。Inspector で個別に変更することもできます。

#### emissionPropertyName（この対象だけの色検出用）

「振り分け」ステップがこのオブジェクトの Emission 色を読み取るときに使うプロパティ名です。**実行時の明るさ切り替えには使われません。** 実行時に効くのは [LightmapChanger の `emissionPropertyName`](#lightemission-制御) 1本だけで、こちらの値と異なっていても、実行時の切り替え自体は LightmapChanger 側の値で行われます。自作シェーダーの発光プロパティ名が `_EmissionColor` と違う場合は、振り分け時の色検出のためにここを合わせてください。ただし、シーン内で発光プロパティ名が異なるシェーダーを混在させる構成は現状サポートしていません。

## ShaderConversionExclude（シェーダー変換からの除外マーカー）

このコンポーネントを親オブジェクトに追加すると、その配下のすべてのレンダラーがシェーダー一括変換の対象から除外されます。

### 設定項目

設定項目はありません。コンポーネントを追加するだけで機能します。

### 使いどころ

- 常に明るく見せたいモニター・TV 画面（消灯時にも周りと一緒に暗くしたくないもの）
- Light Volume を参照する動的投影シェーダーで Emission が動いているオブジェクト（シェーダーを置き換えると動的演出が壊れるため）
- その他、独自のシェーダー演出が組まれていて置き換えたくないオブジェクト

> 通常のワールド家具（壁・床・小物など）は変換した方が自然な見た目になりますので、特別な事情がなければ除外しないことをおすすめします。
>
> 自前のアニメで Emission が動いているオブジェクト（点滅看板など）は、**シェーダー変換は行ってよい**です。代わりに `LightmapBlendTarget` の `blendGroup` を「常時」にすると、Funwari が Emission を上書きしなくなり、自前アニメと衝突しません。

## 独自 Udon から制御する

自分の UdonSharp スクリプトから点灯/消灯・調光・部屋の切り替えを直接呼びたい場合、`LightmapChanger` の public メソッドを呼び出してください。付属の LuraSwitch2 用スイッチを使わず、独自のギミック（トリガー、タイマー、ゲーム内イベントなど）から操作したいケースを想定しています。

シーン内の `LightmapChanger` を `SerializeField` などで自分のスクリプトへ参照させれば、以下のメソッドをそのまま呼べます。

### 点灯/消灯（クロスフェードあり）

| メソッド | 引数 | 説明 |
|---------|------|------|
| `ToggleLight()` | なし | 現在の点灯/消灯を反転します |
| `TurnOn()` | なし | 点灯状態にします |
| `TurnOff()` | なし | 消灯状態にします |
| `IsLightOn()` | なし（戻り値 `bool`） | 現在の点灯/消灯状態を取得します |

これらは `blendDuration`（既定 1.0 秒）にかけてなめらかに切り替わります。呼び出すと、呼び出したプレイヤーへ**オーナー移譲**（`Networking.SetOwner`）を行い、`RequestSerialization()` で他プレイヤーへ同期します。ネットワーク同期される点灯/消灯フラグを書き換えるため、呼び出し元は「他プレイヤーにも見える状態変化」として扱われます。

### 点灯/消灯（即時・クロスフェードなし）

| メソッド | 引数 | 説明 |
|---------|------|------|
| `SetLightStateImmediate(bool isOn)` | `isOn`: true=点灯 / false=消灯 | クロスフェードを飛ばして即座に状態を切り替えます |

`ToggleLight`/`TurnOn`/`TurnOff` と同じく、オーナー移譲と `RequestSerialization()` を伴います。フェードを待たずに一瞬で切り替えたい場合（Late Joiner の初期化直後の同期など）に使います。

### 調光（連続値、スライダー用）

| メソッド | 引数 | 説明 |
|---------|------|------|
| `SetBlendFactor(float factor)` | `factor`: 0〜1（範囲外は自動でクランプ） | ブレンド値を直接指定します。0.5 を境に点灯/消灯フラグも更新されます |
| `GetBlendFactor()` | なし（戻り値 `float`） | 現在のブレンド値を取得します |
| `IsBlending()` | なし（戻り値 `bool`） | クロスフェードの遷移中かどうかを取得します |

**`SetBlendFactor` はネットワーク同期しません。** `RequestSerialization()` を呼ばないため、他プレイヤーには反映されないローカル専用の操作です。全プレイヤー共通の状態にしたい場合は、代わりに `TurnOn`/`TurnOff`/`SetLightStateImmediate` を使うか、呼び出し側で独自に同期を行ってください。また `LightmapChanger` の初期化前（`Start()` 完了前）に呼ぶと無視されます。

### 昼夜

| メソッド | 引数 | 説明 |
|---------|------|------|
| `SetDaylight(float value)` | `value`: 0〜1（0=夜、1=昼、範囲外は自動でクランプ） | 昼夜の値を設定します |

点灯/消灯とは**別の軸**です。`SetDaylight` を呼んでも点灯/消灯状態は変わりません。フィールドへの直接代入でも次の `Update()` で反映されますが、呼び分けを明示したい場合はこちらを使います。`SetBlendFactor` と同様、ネットワーク同期はしません。

### 部屋別調光

| メソッド | 引数 | 説明 |
|---------|------|------|
| `SetRoomBlendTarget(int room, float target)` | `room`: 部屋インデックス（0始まり）、`target`: 0〜1（範囲外は自動でクランプ） | 指定した部屋の調光目標値を設定します |
| `GetRoomBlendFactor(int room)` | `room`: 部屋インデックス | 現在の調光値を取得します（範囲外は `1` を返します） |

`room` が `0` 未満、または `roomCount`（設定済みの部屋数）以上のときは**無音で何もしません**（例外もログも出ません）。部屋別調光を使っていないシーン（`roomCount == 0`）で呼んでも同様に無視されます。こちらもネットワーク同期はしません。

### 映り込みの強さ

| メソッド | 引数 | 説明 |
|---------|------|------|
| `SetReflectionProbeOnIntensity(float intensity)` | `intensity`: 0以上（負値は 0 にクランプ） | 点灯時 Reflection Probe の強度を設定します |
| `SetReflectionProbeOffIntensity(float intensity)` | 同上 | 消灯時 Reflection Probe の強度を設定します |

### 参考実装（Scripts フォルダ内）

いずれも上記メソッドを実際に呼んでいる最小サンプルです。独自のUdonギミックの配線を組む際の参考にしてください。

| スクリプト | 呼んでいるメソッド |
|-----------|------------------|
| `Controller_LightmapBlend.cs` | `SetBlendFactor` — スライダーの `_value`（0〜1）をそのまま渡す |
| `Controller_FunwariDaylight.cs` | `SetDaylight` — スイッチ/スライダー、または GameObject の有効・無効（`OnEnable`/`OnDisable`）から昼夜を切り替える |
| `FunwariRoomSync.cs` | `SetRoomBlendTarget` — スライダーの `_value` を指定した部屋インデックスへ渡す |
| `FunwariRoomToggleButton.cs` | `FunwariRoomSync.OnValueChanged()` 経由で `SetRoomBlendTarget` を呼ぶ — 押すたびに `onValue`/`offValue` を往復するトグルボタン |

`ToggleLight`/`TurnOn`/`TurnOff`/`SetLightStateImmediate` を直接呼ぶ参考実装は同梱していません。呼び出し方はこのページの表のとおりシンプルなので、上記4スクリプトの書き方（対象への参照を持ち、public メソッドを1行呼ぶだけ）を踏襲すれば足ります。

### Switches プレハブとの関係

`Switches/` フォルダの `Slider_Night.prefab` は `Controller_LightmapBlend` を内部に持ち、LuraSwitch2 のスライダーの値変化から `OnValueChanged()`（内部で `SetBlendFactor` を呼びます）を呼ぶ配線がすでに組まれています（プレハブ単体では `targetLightmapChanger` は未設定なので、配置後にシーンの `LightmapChanger` をドラッグ＆ドロップしてください）。`Switch_Light.prefab` は `LightmapChanger_ON` / `LightmapChanger_OFF` を内蔵し、LuraSwitch2 のアニメーターが ON 側・OFF 側の子オブジェクトを切り替えたときに `OnEnable` から `TurnOn()` / `TurnOff()` を呼びます（オーナーだけが呼ぶ。スライダーが設定した途中の明るさを尊重するため、既に同じ状態なら何もしません）。独自の点灯/消灯スイッチを組む場合は、`LightmapChanger_ON.cs` か `Controller_LightmapBlend.cs` を参考に、`ToggleLight`/`TurnOn`/`TurnOff` を呼ぶ薄いブリッジスクリプトを自作するか、`FunwariRoomToggleButton.cs` と同じ構成（トグル状態を自前で持ち、`SendCustomEvent` で呼ばれる public メソッドから対象の public API を1行呼ぶ）を流用してください。

## よく触る設定まとめ

セットアップが終わったあとに、見た目を微調整するためによく触る設定の早見表です。

| 触りたいこと | コンポーネント | 設定項目 |
|-------------|---------------|---------|
| 消灯時の全体的な明るさ | LightmapChanger | `ambientIntensityOff` |
| 消灯時の色味（夜の青さなど） | LightmapChanger | `ambientColorOff` |
| 消灯時の映り込みの強さ | LightmapChanger | `reflectionOffIntensity` |
| 消え方（明るい場所の粘り） | LightmapChanger | 「仕上げ」ステップの「明るい場所の粘り」スライダー（内部値: `dimCurveTau`） |

| 切り替え時の緩急 | LightmapChanger | `useEasing` |
| 個別のライトの振り分け変更 | LightmapBlendTarget | `blendGroup` |

## 既知の制限（1.6.0）

- **部屋のスライダーを作り直すと編集が消えます。** 工程5「ベイク」の「マスクと結線をやり直す」は、部屋のスライダーを削除して作り直します。スライダーに追加した設定や、他のオブジェクトからスライダーへの参照は保持されません。作り直す前に控えてください。
- **部屋のボタンは自分の押した回数で状態を切り替えます。** スライダーや他の人の操作で部屋の状態が変わったあとは、ボタンの最初の一押しが効かないように見えることがあります。同じ部屋にはボタンかスライダーのどちらか一方を置くのが確実です。
- **部屋の後処理が途中で失敗すると、一部の成果物だけが更新された状態になることがあります。** そのときは「マスクと結線をやり直す」を実行し直してください。
- **プレビューには Light Volume・リアルタイムライト・発光・スカイボックスは映りません。** 仕上げのライブプレビューも同じです。Play モードで確かめてください。
